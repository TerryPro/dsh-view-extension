dsh-diff-view: icon mode control, and copy that survives a stale dictionary

The mode chips read `files.mode.preview` on a live page while `已保存` on the same
row read fine. The cause is in the shell's locale service: `register` THROWS when
a namespace+locale is registered twice ("already has locale zh"), which is exactly
what a plugin reload does, and it then keeps the dictionary from the FIRST load.
A key added by a later bundle therefore resolves to itself through the shell's `t`
-- while a key that existed in the first dictionary resolves normally.

Two fixes:
- registering and binding are now separate attempts. They shared one try-block, so
  the throw left `bound` undefined for the life of the reloaded plugin;
- the views take the plugin's OWN translator (passed through `inject` as `tr`) and
  use it for their copy, falling back to the dictionary that shipped with this
  bundle whenever the shell's is missing a key. That also covers every key added
  from now on.

Per the request, the mode control is icons: an eye (preview), a divided frame
(side by side) and a pencil (edit), each with a title and an aria-label, matching
the icon-only head it sits in.

The regression is tested by rendering with a deliberately frozen `t` (one that
answers with raw keys) and asserting the labels still read 预览 / 并排 / 编辑.
