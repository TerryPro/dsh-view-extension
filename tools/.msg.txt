dsh-diff-view: polling is off by default, and a read is not an interaction

The first version polled every FOUR seconds while "active", and re-armed that
active window from every fresh answer ([state.phase, state.files.length]). So the
intended back-off to the slow cadence could never happen: the pane renewed its own
fast window from the refreshes it was scheduling, and polled forever. The per-turn
tab had the same shape (8s unconditional, plus the same self re-arming).

- polling is opt-in now (persisted as dsh-diff-view.auto), default off
- active cadence 4s -> 15s, idle 20s -> 60s
- only real interaction counts as activity
- what replaces the timer: a re-read on window focus / visibilitychange, which is
  the event that actually means "the picture may have moved since you looked"

Tests now assert the pair: nothing is scheduled while polling is off, the toggle
persists, and only then is the next read scheduled.

275 client checks, 170 host checks.
