# dsh-diff-view

给 DeepSeek Harness 会话区加**两个视图页签**，都挂在「对话 / 轨迹」旁边（即轨迹视图的右边）：

| 页签 | 读法 | 布局 |
|---|---|---|
| **变更** | 把这一轮/这个会话**当作一棵树** | 左：改动文件列表；右：选中文件的对比详情 |
| **逐轮** | 把同一份数据**当作一段对话** | 左：每一轮；右上（1/3）：那一轮的提问与最终应答；右下（2/3）：那一轮改过的文件与对比 |
| **文件** | **工作树本身，可编辑** | 左：文件树；右：多标签编辑器（保存走自己的路由，带冲突检测） |

「变更」有两个数据来源，可在面板内切换：

| 范围 | 回答什么问题 | 数据来源 |
|---|---|---|
| **工作区** | 相对 `HEAD` 的**全部未提交改动**（已暂存 + 未暂存 + 未跟踪） | `git status --porcelain=v2` / `git diff HEAD` / 未跟踪文件按新增逐行展示 |
| **本次会话** | 这个会话里 agent **逐轮改过**的文件 | ① Host 的 `workspaceChanges` 记录（按轮次汇总，同一文件多轮改动显示最新一轮并列出所有轮次）；② 会话日志里的 `write`/`edit` 工具调用（在 ① 没有记录时兜底列文件，此时没有前后对比可看） |

### 两条轴：本轮改了什么 · 截至本轮的状态

「本次会话」里有一排**轮次时间线**（`全部轮次` + 每个改动过的轮次，新→旧，各自带一个数字），右侧是**轴切换**：

| 轴 | 回答的问题 | 左栏 | 每行显示 | 右栏 |
|---|---|---|---|---|
| **本轮改动** | 选中的那一轮**改了什么** | 只有那一轮碰过的文件（含它删掉的文件） | 那一轮自己的 `+n −n` 与状态 | 那一轮的前后对比 |
| **累计状态** | 截至选中轮次**结束时，工作区是什么状态** | 到该轮为止仍然**存在**的文件 | 它**最后一次**改动（≤ 该轮）的 `+n −n`、状态、以及 `T{轮}` 标记 | 那次最后改动的对比，表头写明「最后一次改动：第 K 轮」 |

- 同一文件在 3 轮里改过：**本轮改动**里它出现在 3 个轮次视图、数字各不相同；**累计状态**里只出现一次，按最后一次改动呈现。
- 被删掉的文件在**本轮改动**里看得见（那正是这一轮干的事），在**累计状态**里从列表消失、改用「N 个已删除」计数；删了又加回来的会重新出现 —— 折叠只问「最后发生了什么」。
- 轮次 chip 上的数字跟着轴变：本轮改动 = 那一轮改了几个文件；累计状态 = 到那一轮为止共几个文件有改动。
- 轴的选择存在 `localStorage`，和范围选择一样是每浏览器偏好。
- 两条轴都只读**一次**数据：Host 为每个文件返回 `sources: [{ turn, seq, index, status, added, deleted }, …]`（每个改动过它的轮次一条），折叠全在前端做。

**「新增 / 修改 / 删除」是算出来的，记录里没有。** 记录器的 `WorkspaceChangedFile` 只有路径、行数和二进制标记，**没有任何状态字段**；唯一权威是它提供的对比里的 `before`/`after`（哪一侧存在）。所以 Host 会为每个「文件 × 轮次」读一次对比来判定状态，并**按 `seq:index` 缓存**（记录一旦写下就不可变，缓存永远安全；有上限、只在本插件挂载期间保留）。实测：一次列表请求判定 4 个「文件-轮次」，第二次请求一个都不再判定。

### 记一笔：把这一轮落到 git 里

工具条上那个「提交节点」图标按钮是插件**唯一的写操作**。按一下**只是武装**（按钮变成「确认提交？」并说明将发生什么，4 秒后自动解除），再按一下才真的提交。

它做什么、不做什么写得很死：

- 只做 `git add --all` + `git commit`（`--all` 覆盖删除与未跟踪文件，且照旧遵守 `.gitignore`）；
- **不推送、不碰远端、不改写历史、不 amend**；工作区干净时**什么都不做**，返回「没有需要提交的改动」而不是造一个空提交；
- **不跳过仓库自己的 hooks**：一个有 lint/test 门禁的仓库是在对自己的历史提要求，checkpoint 没有资格绕过它 —— hook 拒绝就如实报错，不绕道；
- 提交后**自动重读列表**（这一步是操作的一部分，不是客气）：工作区范围的语义是「对 `HEAD` 的差异」，提交动了 `HEAD`。

为什么值得做：Host 的逐轮记录活在内存里、会话销毁即清空（连同私有 object store 一起删），所以**重启就没了**；而 git 是本来就在、本来就持久、两个范围都懂的那个存储。一轮一次提交同时买到三件事 —— 这一轮的成果跨重启存活；**工作区范围变成"这一轮改了什么"**；`git restore` / `git log` / 外壳自己的卡片全都自然成立，因为它就是一个普通提交。

想让它**每轮收尾自动发生**，在 profile 的 `cordis.patch.yml` 里给这行加配置（默认关闭，因为提交与否是关于**用户历史**的决定）：

```yaml
- id: dsh-diff-view
  name: dsh-diff-view
  config:
    autoCommit: true
    commitMessage: "checkpoint: turn {turn} of {session}"   # 可选，{turn}/{session} 会被替换
```

自动模式挂在 `session/event` 的 `turn/end` 上，**排除子会话**（子代理与父会话共用工作目录、且跑在父会话那一轮**内部**，在它的回合末尾提交会把父会话的一轮劈成两半 —— 这条界线是照抄记录器的），并且串行执行（两个 `git add` 抢 `index.lock` 只会互相失败）；一次失败只记日志、不重试到下一轮。

## 第二个页签：逐轮

「变更」页签旁边的**「逐轮」**把同一份数据当成一段对话来读：

```
┌── 轮次 ────┬──────────────────────────────────────────────────┐
│ 第 3 轮 进行中│ 提问                                             │
│ 第 2 轮 3 +4 −4│ 第二轮：把状态也算出来                          │
│ 第 1 轮 2 +2  │ 最终应答                                         │
│            │ 改完了：两个文件。                                │
│            ├──────────────────────────────────────────────────┤
│            │ 本轮改动  3 个文件 +4 −4                          │
│            │ M keep.txt +4 −1 │ @@ -1,1 +1,2 @@               │
│            │ D gone.txt −3    │ 1 1   first                  │
│            │ A absolute.js    │ 2   + turn-two               │
└────────────┴──────────────────────────────────────────────────┘
```

- **左上**：每一轮的列表（**旧→新，第 1 轮在最上面**），带该轮改动的文件数与 `+n −n`、相对时间，正在跑的那一轮标「进行中」；打开时默认选中**最新**那一轮。
- **右上**：那一轮的**用户提问**（`user/message` 里 `source.kind === 'user'` 的那条）和**最终应答**（该轮**最后**一条 `assistant/message` 的文本，不是第一条 —— 一轮里模型会分多步说话）。注入型上下文（技能正文、文件改动通知、目标续跑）也会作为**兜底**显示，因为"只续跑目标"的一轮其实也说了话。
- **右下（占 2/3）**：那一轮改过的文件 + 选中文件的对比。

**它一半的数据是持久的。** 提问与应答来自**会话日志**（磁盘上，重启后还在），文件对比来自 Host 内存（重启即失）—— 所以几天前的一轮，**问题仍然读得出来**，只是对比会显示「没有留下对比记录」。这也是「逐轮」相对「变更」页签的独立价值：它是一份**可回看的对话记录**，而不只是一个 diff。

两条实现上的要点：

- **轮次归属靠位置**：`user/message` **不带**轮次号，只有 `turn/start` / `turn/end` 带。所以折叠按顺序走日志，把每条消息记到当时"打开着"的那一轮。列表取**两侧的并集**（日志里的轮次 ∪ 记录器知道的轮次），因为日志被压缩过时，某一轮的 `turn/start` 可能没了，而它的改动记录还在；反过来，也有很多一轮什么都没改。
- **文本是截断的**：列表里每条 160 字，详情里 8000 字，截断了就明说（「内容较长，此处只显示前 N 字」）。一次列表请求的文本量因此与轮次数量成正比、与消息长度无关。

### 定时刷新：静默 tick 必须是零成本

「逐轮」和「变更」一样有自动刷新，因此欠同样的保证：**什么都没变的一跳，除了一次列表读取之外什么都不该做** —— 不重读详情、不重读对比、不重建任何元素。

这里踩过一个坑：判断"要不要重读当前轮"时，我拿**合成的单元素数组**去算指纹，而存下来的指纹来自**真实的文件数组** —— 两者永远不可能相等，于是每一跳都走慢路径：重读详情 → 清空已持有的对比 → 重新请求并整棵重建 diff。表现就是"每隔几秒卡一下"。

现在的做法（与「变更」页签同一套纪律）：

- `rowPrint(row)` 只用**读者看得见的事实**做指纹（轮次、是否进行中、文件数、增删行、提问与应答的预览文本）；
- 列表按指纹合并（`mergeRows`），没变的行**保留原对象**；
- 静默 tick 只在**选中行的指纹变了**（或当前没持有详情）时才重读，并且**不清空屏幕上已有的东西**（`selectTurn` 的 `refresh` 分支），内容相同的记录复用原对象，选中的文件若仍在列表里就保持不动，`selectFile` 的去重守卫于是直接返回 —— 零请求、零重建；
- **旧轮次永不重读**：它不可能变，所以在旧轮次上的一跳只花一次列表读取。

实测（测试里直接驱动刷新并计数）：安静一跳 = **1 请求、0 次 store 通知、0 个元素**；只有正在跑的那一轮还在长时才追它，且只读它自己（列表 + 该轮详情 + 它新出现文件的对比）。

### 样式：用外壳自己的词汇，而不是自己发明一套

页签里没有一处是"看起来差不多"的自制样式，能拿到外壳原件的都用原件：

| 部位 | 用的东西 | 出处 |
|---|---|---|
| **最终应答** | 外壳自己的 **`MarkdownText`**（`require('@deepseek-ai/dsh-client-ui-primitives')`）—— 同一套排版、代码围栏、脚注、KaTeX；`labels` 按外壳自己的方式构造并 memo（新对象会丢掉它的流式渲染缓存） | `ui-primitives/markdown/MarkdownText` |
| **提问** | 外壳对话里的**用户气泡**：右对齐、`--dsw-specific-bubble` 填充、`--dsw-radius-xl` 圆角、`padding:10px 16px`、字号/行高走 `--dsh-content-font-size` / `--dsh-content-font-delta` 两根轴 | `ui-chat` `MessageItem.module.css` `.bubble` |
| **文件对比** | 外壳 **`DiffBlock` / `CodeCard`** 的词汇：卡片铺 `--dsw-alias-markdown-code-block` + `--dsw-radius-lg`，正文 `--dsw-font-markdown-code-block`（`11px/19px` 等宽），`- `/`+ ` 用 `::before` 前缀，增删行 = 状态色 + `inset 3px 0 0` 侧条 + `--dsw-alias-code-diff-added/deleted` 底纹，换行走 `data-code-wrap` 属性 | `ui-primitives` `DiffBlock.module.css` / `CodeCard.module.css` |
| **轮次时间** | 外壳自己的 **`relativeTime`** 分桶（`{unit,n}`）+ 与 `ui-workspace` 会话行**同样的措辞**（`刚刚` / `5分钟` / `3小时` …） | `ui-primitives/relative-time`、`ui-workspace/locales` |
| **「进行中」标记** | 外壳的 **`Tag`**（`tone="info"`） | `ui-primitives/Tag.tsx` |

- **删掉了行号栏。** 之前那套「旧行号 / 新行号 / 符号 / 文本」四列是 VSCode 的样子，外壳自己的 diff **没有行号**，只有前缀、色条和底色 —— 一眼就能看出不是同一个应用。hunk 头（`@@ … @@`）按外壳 `.gap` 的做法处理成弱化等宽行。

### 输入框只在「对话」页签出现

外壳把 composer 座位渲染成**当前页签的兄弟节点**，所以默认它跟着读者走进任何页签 —— 在 diff / 逐轮 里既没有可发送的对象，又吃掉整高面板的底部。外壳**没有**按页签隐藏的开关（`DefaultConversationViews` 的注释明确说输入框留在 `ConversationRoot`，轨迹视图更是主动加 overlay 契约让输入框浮在自己上面）。

但外壳保证了这条规则需要的信号：视图宿主**同一时刻只渲染一个页签**（`renderSlot('conversation.view', …, { only: viewId })`），所以"滚动体里出现了哪个页签的根节点"就等于"当前选中的是哪个页签"。于是：

```css
[data-conversation-scroll]:has([data-dsh-diff-view])>[data-composer-seat],
[data-conversation-scroll]:has([data-dsh-diff-turns])>[data-composer-seat],
[data-conversation-scroll]:has([data-conversation-composer-overlay])>[data-composer-seat]{display:none}
```

- 前两条是**本插件自己的两个页签**（用它们各自的根节点标记，改名就会失效——所以测试把"选择器里的属性"和"根节点上的属性"两半都钉住了）；
- 第三条覆盖**任何**取用外壳 overlay 契约的全高视图（轨迹视图就是），语义是"自己拥有整块面板的视图不携带对话的输入框"；
- 用 `display:none` 而不是卸载：DOM 不动、草稿不丢，切回对话页签规则的匹配立刻消失。

**代价**：在我这两个页签里**不能直接发消息**（这正是"限定到会话视图"的字面含义）。想要只影响本插件两个页签、不动轨迹视图，删掉第三条即可。

### 输入框为什么"贴在"面板底部

外壳里输入框**不是对话页签的一部分**，而是所有页签的兄弟节点（`ConversationContent` 在同一个 `scrollBody` 里渲染 `<Views/>` 与 composer 座位，active 阶段座位是 `position:sticky;bottom:0`）。但对**自带滚动条的全高视图**（轨迹、以及本插件的两个页签），外壳提供了开关 `data-conversation-composer-overlay`：加上它，会话的滚动体变成裁剪盒，输入框座位改成 `position:absolute;bottom:0` **浮在视图底部**；同时视图必须自己让出底部空间 —— 外壳把座位实时高度发布为 `--dsh-composer-height`。

本插件的两个页签都取了这个契约：根节点带 `data-conversation-composer-overlay`，并声明 `--dshdv-bottom-clearance: calc(var(--dsh-composer-height, 152px) + 16px)`，每个内部滚动区用它做 `padding-bottom`（与 `ui-trajectory` 的做法一致）。**缺任何一半都会坏**：只有属性没让位 → 最后一行被浮起的输入框压住；只有让位没属性 → 在并不存在浮动输入框的地方空出一块。测试把两半都钉住了。

### 按钮的盒子必须装得下它的标签（一个真实缺陷的教训）

`.dshdv-btn` 曾是**图标按钮**：固定 `width:28px`。后来我把文字标签（「预览」「编辑」「高亮」「重试」「仍然覆盖」…共 11 处）塞进同一个类，结果每个字被挤成一列 —— 编辑器头部本该 32px 高，变成了一竖排字母，路径列被压到 0 宽。

改法只有一条 CSS：`width:28px` → **`min-width:28px` + `white-space:nowrap`**。图标按钮依然是 28×28（16px 图标 + 6+6 内边距），文字按钮则自己撑开。

这个缺陷**测试当时抓不到**：harness 里没有布局引擎，DOM 断言看不见"字被挤成竖排"。所以护栏写在**规则**上而不是 DOM 上：

```js
check('the button box grows with its label', btnRule.includes('min-width:28px') && !/(?<!min-)width:28px/u.test(btnRule))
check('a button label never wraps', btnRule.includes('white-space:nowrap'))
check('the editor head cannot be forced taller by a wrapping label', fileHeadRule.includes('min-height:32px'))
check('header labels are translated, not raw keys', ...)   // 原始键出现在界面上 = 字典缺条目
```
### 一个隐蔽的陷阱：外壳的字典会被"冻"在第一次加载

现象：模式控件的三个标签显示成 `files.mode.preview` / `files.mode.split` / `files.mode.edit`，而同一行的 `已保存` 正常。

链条是这样的（外壳 `packages/client/locale/src/client/index.ts:399-419`）：

```ts
if (locales.has(localeKey(locale))) throw new Error(`locale namespace "${ns}" already has locale "${locale}"`)
```

`register` 对"同一命名空间+同一语言"的**第二次注册直接抛错** —— 而插件重载恰恰就是第二次。抛错后外壳**保留第一次加载时的那份字典**，于是后来新增的键在 `props.t` 里查不到、原样返回键名；`files.saved` 因为第一次就有，所以正常。

两个修法（都已落地）：

1. `register` 与 `bind` **分开 try**。原来共用一个 try，抛错后 `bound` 永远是 `undefined`；
2. 视图文案**走本插件自己的翻译器**（`inject` 里作为 `tr` 传入）—— 外壳字典缺哪个键，就用随这个包一起发布的字典兜住。这条对"以后再加键"同样有效。

护栏是一条**构造出来的回归测试**：用一个 `t: key => key` 的"冻结字典"渲染，断言标签仍然读出 `预览 / 并排 / 编辑`。
#### 字体：用外壳那条代码字简写，而不是"看起来差不多"

第一版我把编辑器根部设成 `--dsh-content-font-size-secondary`（13px）+ `line-height:1.6`，于是字号与行高都和外壳自己的代码块不同 —— 一眼就能看出"这不是同一个字"。

外壳的代码字只有一条来源：

```css
--dsw-font-markdown-code-block: 11px/19px var(--ds-font-family-code);
```

### 编辑器换成了 CodeMirror（懒加载分块 + 兜底）

原来那套「textarea + 高亮叠加层 + 自绘行号槽」是**真编辑器缺席时的替代品**。现在接上了 CodeMirror 6，走的是加载器的**包内懒加载分块**机制：

- 分块 `client/client.editor.js`（**591 KB**，已提交）—— 用户不需要构建；`tools/editor-entry.js` + `tools/build-editor.mjs` 记录了它是怎么打出来的（`npm run build:editor`）。
- 加载器把 `require.async('./client.editor.js')` 解析成 **`/plugins/<插件id>/client.editor.js`**，并要求该文件以 `__ModuleLoader__.load({ id: "dsh-diff-view/client.editor.js", … })` 注册自己；文件名还必须匹配它那条 `^client\.[A-Za-z0-9][A-Za-z0-9._-]*\.js$` 规则。这三点我都实测过（200 / 605 209 字节）。
- **没有用 `@codemirror/language-data`**：它靠动态 `import()` 解析语法，会再切出分块，而这个加载器**每个插件只服务一个兄弟文件**；语法是显式内联的 6 组（js/ts/jsx/tsx、json、html、css/scss、markdown、python）。
- **失败即退回**：分块取不到（加载器没有 `require.async`、网络失败、旧包）时，原来的 textarea 编辑器继续用 —— 这不是装饰性的兼容，而是"插件不能因为一个可选库而不可用"。
- 每个标签一个 `EditorView`，与标签同生共死：**文档、撤销历史、选区都跨标签切换保留**（和 textarea 时代同一性质）；`Mod-s` 仍走本插件的保存（`(mtime, bytes)` 冲突检测不变）。

于是白拿了这些：**Tab / Shift+Tab 缩进**、`Ctrl+F` 文件内搜索、括号匹配与自动闭合、撤销历史、活动行高亮。
### 谁有预览、谁只有编辑器（按你的建议收窄了模型）

| 类型 | 表面 |
|---|---|
| `.md` `.markdown` | **三种**：预览 / **并排**（左源码右文档）/ 编辑 —— Markdown 是唯一"源码与渲染都值得看"的类型 |
| `.js` `.ts` `.json` `.yaml` `.html` `.css` … 一切代码与文本 | **只有一种**：高亮编辑器（VS Code 的做法，源码就是这个文件的样子） |
| 图片 / PDF / Office / 二进制 / 超大 | 交给外壳的预览器 + 下载 |

**高亮怎么做出来的**（外壳没有"可编辑的高亮控件"，`CodeBlock` 是只读的，而本插件没有构建步骤、装不了 CodeMirror）：

```
┌─ .dshdv-fvCode ─────────────────────────────┐
│ .dshdv-fvGutter   ← 行号（窗口 + 位移层）      │
│ .dshdv-fvCodeLayer ← 外壳 useCodeHighlighter 的每行 token │
│ textarea .dshdv-fvGhost ← 字形透明、**光标可见** │
└─────────────────────────────────────────────┘
```

三层都靠 `transform` 跟随 textarea 的滚动（不重排、不重渲染）。成立的前提是**两层度量逐字一致**：同一个 `font` 简写（因此行盒固定 19px）、同一份 `padding`、`white-space:pre`、`tab-size:2`，外加 `wrap="off"` —— 这样"一行源码 = 一行 19px 行盒"，无论该行有多少个 token 片段。

打字**从不等待语法解析**：`onInput` 把纯文本直接写进层里（一次字符串赋值，无 React 渲染），高亮版本在 **120ms 去抖**后到达；超过 4000 行则只走纯文本路径。

行号数的是 `split('\n').length` —— 末尾换行后的那个空行**也要编号**，因为 textarea 里光标能停上去；纯文本路径末尾补一个零宽字符，否则 `<pre>` 会吃掉末尾换行而少一行（这一条被测试抓到了）。

我在浏览器里无法验证"像素级对齐"，所以把**度量契约本身**写成了断言：

```js
check('the layer and the textarea agree on every metric', metricsOf(inputRule) === metricsOf(layerRule))
check('the gutter shares the code font and its first-line offset', ...)
check('the ghosted textarea keeps a visible caret', ...)   // 字形透明但光标必须看得见
```
### 各类文件怎么浏览、哪些能编辑

参考 `DSH-better-sidebar` 的 `src/client/builtins/viewers.tsx`，它自己写了一句决定性的判断：

> DSH 0.1.7 ships `ui-sidebar-documentpreview`, its own code / spreadsheet / office / pdf / image / html / markdown / text previews with zoom and auto-refresh, so this plugin **yields every READ-ONLY preview it used to own** and keeps only the surfaces where it is not equivalent: markdown / html / **code（可编辑）**

所以这里照抄那个判断，**而不是**自己重画图片/PDF/Office 预览：

| 类型 | 在这里 | 说明 |
|---|---|---|
| `.txt` `.json` `.js` … 一切文本 | **编辑**（默认） | 文本域 + `Ctrl/⌘+S` 保存（带冲突检测）；右上可切「高亮」只读（外壳 `CodeBlock`） |
| `.md` `.markdown` | **预览**（默认）→ 可切编辑 | 预览走外壳自己的 `MarkdownText`（表格/代码块/脚注都在），不自己写渲染器 |
| `.html` `.htm` | **预览**（默认）→ 可切编辑 | `<iframe sandbox="">`，**无 `allow-scripts`**，指向本插件的 `/api/dsh-diff/raw` |
| 图片 / PDF / Office / 表格 / 二进制 / 超大 | **交给外壳的预览器** | 面板给出「用外壳预览器打开」+「下载」，地址是外壳语法 `dsh-resource://file/session/<id>/<path>`，经 `ctx.get('sidebarRight').openResource()` |

只读类型**不重画**的理由很实在：外壳那套预览器有缩放、自动刷新、Office/PDF 渲染，我自己写只会更差；反过来，**外壳的预览器不是编辑器**，这正是这个面板存在的意义。

`/api/dsh-diff/raw` 是新的一条路由（HTML 预览的 document URL、图片兜底、下载），与文本读取**共用同一条包含性检查与上限** —— URL 不是绕过它们的办法；`cache-control: no-store`，因为预览的意义就是"现在这个文件的样子"。

> ⚠️ **主机半边需要重新加载**：新增路由要由主机进程重新导入插件才生效（只刷新页面只换浏览器那一半）。未注册的 `/api/*` 路径会被外壳网关答成 **401**，所以「HTML 预览 / 下载」在主机重载前会失败，其余功能不受影响。

## 提交行能显示什么，以及排序

`git log` 一次读取（`--numstat` + 自定义 `--pretty`）就能给出这些，所以**每行不额外起进程**：

| 显示 | 来源 |
|---|---|
| 主题 | `%s` |
| 短 id | `%h` |
| 作者 | `%an`（邮箱在悬停里） |
| 相对时间 | `%aI`（绝对时间在悬停里） |
| **分支 / tag 装饰** | `%D` —— `HEAD -> main`、`tag: v1` 以 chip 显示 |
| **是否合并** | `%P` 的父提交个数 ≥ 2 |
| **改了哪些、多少** | `--numstat` → `N 个文件 +x −y`，有二进制文件时标 `bin` |

为什么用 `--numstat` 而不是 `--shortstat`：后者的文本是**本地化**的（"3 files changed" 在中文 git 下是另一套词），解析它等于把界面绑死在某个语言上。`--numstat` 是制表符分隔的数字。

**排序**：右侧一个图标按钮在「从晚到早 / 从早到晚」之间切换，选择被记住（`dsh-diff-view.historyOrder`）。诚实说明：分页读到的永远是最新的一页（`git log` 的默认），这个开关**在已加载的这一页内**反向，标签也是这么写的。

顺带修掉一处过时文案：仓库缺失时的提示原本还在劝用户"切换到「本次会话」"，而那个作用域已经删了。
## 三栏 + 两条可拖动的分隔条

```
┌──────────────────┬──────────────────────────┐
│ 提交历史（上）     │                          │
├──────────────────┤   详情（该文件的对比）      │
│ 文件列表（下）     │                          │
└──────────────────┴──────────────────────────┘
        ↕ 拖动                        ↕ 拖动
```

- 两条分隔条都是 `role="separator"`，**指针拖动 + 方向键都能调**（←/→ 调左栏宽度，↑/↓ 调上下比例），各 16px / 4% 一步。
- 几何值放在容器的 CSS 变量上（`--dshdv-left-w`、`--dshdv-left-split`）：拖动时**每次 pointermove 只写一个变量，不触发 React 渲染**，松手时才落一次状态并持久化（`dsh-diff-view.leftWidth` / `.leftSplit`）。
- 上下的比例**按百分比存**，所以改窗口大小不会把布局弄坏；宽度按像素存，并有上下限（180–720px，且不超过容器的 70%）。
- 单位混用是这一版的真实 bug：第一版把"像素位移"加到"百分比"上，分隔条会跳到荒谬的值 —— 现在手势内部一律用像素，只在存储时换算成比例。
## 一条全局约定：行不许贴在一起（以及 tooltip 不许复述那一行）

同一个问题我修了三次才意识到它是**一条约定**，而不是三个 bug：

| 实例 | 现象 |
|---|---|
| 提交行 | 两行文字贴在一起，悬停/选中底色连成一块；tooltip 复述主题、盖住下一行 |
| 浏览器的文件行 | 同上；tooltip 复述状态词「修改」，而 `M` 就在行上 |
| 文件树 / 逐轮的文件行 | 同样贴在一起 |

约定，写进 CSS：

```css
.dshdv-gitHistory .dshdv-listBody,
.dshdv-gitFiles   .dshdv-listBody,
.dshdv-fvLevel,
.dshdv-tvFileList   { display:flex; flex-direction:column; gap:2~3px }
```

配套的第二条：**tooltip 只放行上挤不下的东西**（完整路径 / 目录 / 绝对时间 / 分支装饰），放行上已有的内容不只是冗余 —— 那把 tooltip 会变宽，然后**遮住你正要读的下一行**。文件树因此这样处理：行上显示的是名字、层级已经说明了位置，所以 hover 只补**目录**，根目录下的文件**干脆没有 tooltip**。

护栏是一组：对四个列表逐个断言"有 gap"，并在真实渲染上断言"根级行没有 tooltip、嵌套行的 tooltip 只是目录"。
## 分支状态、推送、单文件历史（参考 VS Code 的三项）

| 加了什么 | 怎么工作 |
|---|---|
| **分支与同步状态** | 条形栏显示 `⎇ main`、`↑2`（领先上游）、`未发布`、`合并中 / 变基中`、`游离 HEAD`、`还没有提交`。一条 `git status --porcelain=v2 --branch` 给出分支/上游/领先落后；合并与变基状态读的是 git 自己写的标记文件（`MERGE_HEAD`、`rebase-merge|apply`），因为 `status` 不报它们 |
| **推送 / 发布分支** | 只有"领先上游"或"没有上游"时才出现。**两段式**（和「记一笔」同样的纪律）：第一下变成「确认推送 / 确认发布」，第二下才执行，4 秒不动自动解除。有上游就是 `git push`，没有就是 `--set-upstream origin <分支>` |
| **单文件历史** | 对比详情头部一个按钮：列出**改过这个文件**的提交（`git log --follow` —— 改过名的文件保留旧名的历史），每条带它对该文件的 `+x −y`；点一条就把窗格**钉到那一版**（`scope=commit&at=<sha>`），头部显示「第 cccccc 版」并给出返回当前 |

关于 push 有一条刻意的设计：**失败时原样转述 git 的话**。远端连不上和凭据缺失需要完全不同的修法，而只有 git 知道是哪一种 —— 所以我把它当成结果展示，而不是翻译成一句友好的猜测。

**诚实交代覆盖缺口**：这三项的 Host 侧有 15 条断言（分支/上游/领先落后、`--follow` 的文件历史、只统计该文件的行数、push 拒绝 GET、不可达远端时原样返回 git 的消息）。**客户端侧这一轮没有留下自动化断言** —— 我在推进"文件钉版 / 推送两段式"的用例时撞上了 harness 的控制器实例身份问题（卸载后缓存清空，测试持有的控制器与视图渲染用的不是同一个），调试到预算边缘后我选择**回滚测试文件**（318 条全绿）而不是留下一堆红条或为了通过而改产品。这两条路径需要人工确认一次。
## 分隔视图的重叠：flex 收缩的是盒子，不是字

截图现象：并排对比里两列的文字**互相压在一起**。

```css
.dshdv-splitCell{flex:1 1 50%; min-width:0; white-space:pre}   /* 没有 overflow */
```

`flex:1 1 50%` + `min-width:0` 只保证**盒子**能被压缩到 50%；而 `white-space:pre` 让长行不换行，**字形照样画到盒子外面**，于是直接盖在隔壁列上。两个修法：

1. **裁剪**：`.dshdv-splitCell{overflow:hidden}` —— 单元格内的内容永远不出格。
2. **让换行开关在分栏里也生效**：原来单元格硬编码 `white-space:pre`，`data-code-wrap` 对它无效 —— 也就是说"换行"这个开关在分隔视图里**被静默忽略**了。现在补上 `.dshdv-code[data-code-wrap="true"] .dshdv-splitCell{white-space:pre-wrap;overflow-wrap:anywhere}`，默认（换行开）下长行在自己的格子里折行，什么都不会被裁掉。

顺带确认了一件没坏的事：`splitRows` 的配对是对的（删除与新增按序号配对，缺的一侧留空单元格），所以两列始终逐行对应，不会错位。
## 空窗格不该是滚动容器

截图里的现象：窗格已经空了（"当前范围没有改动"），右侧却仍有一条滚动条槽。成因是**真的溢出**，不是观感问题：

```css
.dshdv-status{height:100%; padding:24px}   /* 没有 border-box → 比窗格高出 48px */
.dshdv-listBody{overflow:auto; scrollbar-gutter:stable}  /* 且常驻保留滚动条槽 */
```

于是空状态把自己撑出了滚动条，而 `scrollbar-gutter:stable` 让那条槽永远可见。两处一起修：

1. **结构**：没有内容要列时**根本不渲染滚动容器** —— 状态块直接作为窗格的孩子（`.dshdv-paneEmpty{overflow:hidden}`）。没有滚动容器，就没有滚动条、也没有槽。有内容时才渲染 `.dshdv-listBody`。
2. **防御**：`.dshdv-status` 加 `box-sizing:border-box; min-height:0` —— 无论它将来被放进什么容器，都不可能再因为"高度 100% + 内边距"而溢出。
3. 列表**内部**的提示（例如历史读取失败）改用 `.dshdv-statusInline`（`height:auto`），否则它会占满整屏、把上面的"工作区"行挤出视野。

护栏：`.dshdv-status` 必须含 `box-sizing:border-box`；空窗格必须 `overflow:hidden` 且**不得**带 `scrollbar-gutter`；并在真实渲染上断言"空列表的元素不带滚动类、有行时才是滚动容器"。
## 自动刷新：默认关闭（一次设计缺陷的修正）

第一版是这样写的：**活跃时每 4 秒**读一次，20 秒退到慢速，而"活跃"= 距上次交互**或上次读到新数据** 30 秒内。最后半句是致命的 —— 我写了一个 `[state.phase, state.files.length]` 的 effect，于是**每次刷新读到新数据又把自己标记为活跃**，退化成慢速这件事永远不会发生：4 秒轮询自我续命，永久跑下去。逐轮页签同样（8 秒无条件，外加同样的自我续命）。

现在的策略：

| | 之前 | 现在 |
|---|---|---|
| 默认 | 开 | **关**（偏好键 `dsh-diff-view.auto`，可持久化） |
| 活跃节拍 | 4 秒 | 15 秒 |
| 空闲节拍 | 20 秒 | 60 秒 |
| 谁算"活跃" | 交互 **或读到新数据** | **只有真实交互** |
| 定时器之外 | 无 | **窗口重新获得焦点 / 页面重新可见时补读一次**（`focus` + `visibilitychange`） |

理由写在代码注释里，避免以后又被改回去：**一次读取不是一次交互**；而且"回到这个页面"这个事件本来就等价于"你可能想看最新的了"，它比一个永远在问的定时器更准、更省。
## 第一个页签：Git 浏览（原来是「变更」）

改的原因很直接：**每轮"记一笔"之后工作区通常是干净的**，所以"工作区 vs HEAD"的变更视图经常空着 —— 而历史才是真正会看的东西。

左栏是提交列表，**第一行是「工作区（未提交）」**：

| 选中 | 右栏（上 1/3 文件，下 2/3 对比） |
|---|---|
| 工作区 | 未提交的改动文件，对比走 `git diff HEAD` |
| 某个提交 | **那个提交自己的文件**（`diff-tree --root --first-parent`）与 `scope=commit&at=<sha>` 的对比 |

- 「记一笔」提交按钮**保留**（它是唯一的写操作）；提交后**历史会重读**，新提交立刻出现在第一行。
- 提交列表的 `--root` 让**仓库的第一个提交**也能浏览（对空树做 diff），`--first-parent` 让合并提交对着它合入的那条分支读，而不是变成一个单文件视图无法渲染的组合 diff。
- 历史读取失败只在「工作区」行**下面**出一条提示 —— 那一行是唯一不需要仓库也成立的东西，不能被整块错误页取代。
- 搜索框改为**搜索提交**（主题 / sha 前缀）。
- 按你的选择，**「本次会话」作用域直接去掉了**（逐轮页签已经能按轮次看文件改动）；工作区/会话两套作用域切换、轮次筛选条、delta/state 两种轴一并移除，相关样式也删了。
- 已知遗留：控制器里仍保留会话作用域那几个动作（`setScope`/`setTurn`/`setMode` 与按轮次取对比的路径），界面上已无法到达 —— 下次清理时一并删掉，眼下不动它是为了不牵动已通过的取数逻辑。
## 第三个页签：文件（树 + 多标签编辑器）

参考两个已装插件：`dsh-vscode`（文件面板）与 `dsh-better-sidebar`（标签工作台 + CodeMirror 编辑器）。调研结论直接决定了实现方式：

| 参考做法 | 我怎么办 | 原因 |
|---|---|---|
| `dsh-vscode` 是**纯浏览器插件**：`inject: ['slots','locale','layout','remote','remote.workspaceFiles']`，用 `workspaceFiles.list/changes` 列目录，打开文件**委托给外壳右栏的文档预览** | 列目录与读文件走**我自己的主机路由** | 外壳的 `workspaceFiles` **没有写**，而 `stat.version` 是**不可解析的不透明令牌**，没法和我这边的写检查对上 |
| `dsh-better-sidebar` 读写全走**自建 `/sidebar/*` 路由**，写用 tmp+rename 原子化 | 同样自建，但只做三件事：`tree` / `read` / `write` | 一套路径安全（`joinUnder`，越界即拒）、一套新鲜度语义 |
| 它的编辑器是 **CodeMirror 6**，而且是**懒加载分块**（2MB，自建 `/sidebar/bundle` 路由 + 打包器） | **文本域**（无构建步骤，装不了那个依赖）+ 外壳自己的 **`CodeBlock`** 做"高亮"只读模式 | 我无法在这里用浏览器验证"高亮层 + 透明文本域"的对齐，风险不值得 |
| 它的**每个标签保持挂载**（非激活只是隐藏），所以切标签不丢草稿 | 同样：每个已打开文件一个 pane，非激活 `hidden` | 卸载 textarea 就是丢草稿 —— 我第一版正是这么写的，被测试抓到 |
| 它的 READ-ONLY 高亮用外壳 primitive；**关标签不确认**、**无 revert**、**dirty 不持久化** | 关标签**先确认**、有「重新载入」、脏标记在标签上 | 这三件是它的已知缺口 |

保存的冲突检测是这一版的核心：读文件返回 `(mtimeMs, bytes)`，保存把这一对带回去，Host 在写之前重新 `stat` 比对 —— 不一致就 **409 拒绝**，界面给出「仍然覆盖 / 重新载入」，**绝不静默覆盖**。

参考实现踩过的坑也照单收了：`<style>` 必须打 `data-plugin`（否则会被下一个物化的插件认领并在它卸载时删掉）、`:has()` 主体要窄、`scrollbar-gutter: stable`、目录级生成号（同一路径后发赢）。
## 它为什么长这样

**两个视图页签，不是新开一栏。** 轨迹视图本来就占满会话区中栏，所以「轨迹旁边的 diff」就是轨迹的兄弟页签，而不是新的一栏。外壳已经有这个座位：`conversation.view`（`DefaultConversationViews` 一次只渲染一个条目）。插件往这个列表里加两项（`diff` / `turns`），就白拿了页签条、会话作用域和生命周期；卸载即完全消失，没有任何 DOM 手术。

**Host 出数据，浏览器出画。** 浏览器跑不了 `git`，也读不到会话的逐轮改动记录（那在 Host 内存里），所以两者都由插件的 Host 半边算好，通过 `/api/dsh-diff/*` 以 JSON 返回：
| 路由 | 方法 | 作用 |
|---|---|---|
| `/api/dsh-diff/files` | GET | 某个范围（`git` / `session`）的改动文件、状态与行数 |
| `/api/dsh-diff/file` | GET | 单个文件的结构化 hunks |
| `/api/dsh-diff/turns` | GET | 某个会话的每一轮：提问、应答、改动文件数（新→旧，文本截断到 160 字） |
| `/api/dsh-diff/turn` | GET | 某一轮的全文：提问、应答、该轮改动的文件与各自坐标（文本截断到 8000 字） |
| `/api/dsh-diff/commit` | POST | 提交这个会话的工作区（唯一写操作，见上文「记一笔」） |

请求**只带会话 id，不带路径**：工作目录由 Host 从会话自己的 header 解析（优先 `sessionQuery`，回退到活跃 agent 表）。所以构造请求最多只能指定一个用户本来就开着的会话，无法让插件去读任意目录。

**行数用一条 `git diff --numstat` 拿。** 已暂存和未暂存的改动**合并**报告（`git diff HEAD`），所以同一文件的两处改动不会各算一次；未跟踪文件没有 index 条目，由 Host 自己按行数计，二进制和超限分别降级成「二进制」和「不计数」。

**每次请求要付的钱，被认真数过。** Windows 上一条 git 命令光进程创建就 ~40 ms，所以读路径按「一次请求最少几条命令」设计：

| 请求 | git 命令 | 说明 |
|---|---|---|
| 工作区列表 | 2 条（`status` + `diff --numstat`，并行） | 一次拿全所有文件的改动与行数 |
| 单文件对比（已跟踪、有改动） | **1 条**（`git diff HEAD -- <path>`） | 对比先跑：它自己就能回答常见情况，不必先花一次 `status` 去问「这是什么状态」 |
| 单文件对比（未跟踪 / 无改动） | 2 条 | 只有空 diff 是歧义的，这时才值得再问一次 status |

另外三处「同样的东西不要重复算」：

- **会话工作目录从内存拿**：`ctx.sessions.get(id).header.cwd` 是活的会话表，微秒级；而 `sessionQuery.readSession` 要读并重放整份会话日志 —— 会话长到几千个事件时是**几百毫秒，且随会话增长**。日志只在会话已不在 Host 里时兜底。实测线上：1.2 MB 的会话日志重放占了单文件请求 725 ms 里的大头。
- **git 路径与仓库根各自缓存**：可执行文件 60 秒、仓库根 10 秒（工作树不会跑掉）。这些缓存只存路径与根、绝不存文件内容，所以过期最多多查一次，不会给出错误对比。
- **会话日志解码缓存 1 秒、最多 4 个会话**：只用来把一次交互内的重复读合并掉；一秒旧的改动列表还是改动列表。

改完的离线实测（真实 git、真实路由代码、活会话）：列表冷启 148 ms → 热 **34 ms**；单文件对比热 **26–49 ms**（含 28 KB 大文件）；会话日志重放 **0 次**。

**`--line-prefix` 是分隔符，不是装饰。** `git diff` 的正文行可能本身就以 `diff --git`、`--- ` 或 `@@` 开头。Host 给每一行加一个路径里不可能出现的控制字符，然后先剥标记再分类，于是「正文里的 `@@`」和「hunk 头」永远不会混淆。

**重命名不做重命名检测。** 列表把 `R old → new` 作为元信息画出来，但单个文件的对比**故意不加 `-M`**：给了单个 pathspec 之后，`-M` 可能判定「这是个全新文件、和原来没差别」，而这是对比最不该给出的答案。

**复制路径按钮**用 `navigator.clipboard`（不可用时静默失败），**换行偏好**存在浏览器 `localStorage`，和外壳其它布局状态放在一起。

## 它刻意不做的事

- **不做语法高亮**：外壳的高亮器是打包进去的服务，第三方 bundle 引用不到（`require` 只认平台白名单里的名字）；半亮不亮的 diff 比朴素的更难读。
- **不写入**：没有 stage / revert / 保存，路由全部只读。
- **不读任意目录**：见上面的会话寻址。
- **不缓存**：换一次会话就重新读一次——diff 是移动中的工作区的快照，陈旧的比转圈更糟。

## 布局与交互

- 顶部：范围切换、文件数与 +/− 汇总、文件名筛选、自动刷新开关、手动刷新
- 左栏：每行一个文件 —— 状态字母（`M`/`A`/`U`/`D`/`R`/`C`/`!`/`B`/`L`）、文件名、所在目录、`+n −n`；键盘可达（`aria-selected` + `listbox`）
  - **选中样式就是外壳自己的样式**，不是这里发明的：行 = `--dsw-alias-label-primary` 墨色 + `--dsw-radius-md` 圆角，悬停与选中**共用同一个**交互填充 `--dsw-alias-interactive-bg-hover` —— 逐字对齐 `ui-workspace` 的 Rows（`.sessionRow.selected`）与 `ui-sidebar-files` 的 FilesBody（`.row:hover`）。此前用过的品牌色底、左侧强调条、加粗文件名都已删掉：那读起来像塞进外壳里的外来控件。工具按钮同样抄自 FilesBody 的 `.tool`（28px 方框、`--dsw-radius-sm`、15px 图形、次级墨色 → 主墨色 + 交互填充），分隔线统一外壳的 `--dsw-alias-border-l3`（0.5px），次级信息统一 `--dsw-alias-label-tertiary`。测试里有一组断言盯着这套词汇，防止再漂回自定义样式。
  - **点一下很便宜**：`FileRow` 用 `React.memo` + 显式比较器（比 `file` / `selected` / `t` 三个引用），行回调用稳定的 `useCallback`（路径作参数，不再每行一个闭包），列表折叠让未变的行**沿用同一个对象**。实测一次点击：**2 次行渲染**（只有选中/取消选中的两行）+ 4 次 memo 跳过 + 1 个请求；列表再长，代价也只跟变化的那两行有关。
- 右栏：文件名、状态、行数、**并排/统一**切换、**换行**切换、复制路径；正文按 hunk 分段，带 `@@` 头、双侧行号、`+`/`-`/空格标记
  - 右栏的 DOM 形状是**载荷**，不是装饰：`.dshdv-main` 这一行只放两个孩子 —— `.dshdv-list` 和 `.dshdv-body`，头部与滚动正文必须作为**同一个**孩子进来。这里若用 Fragment，它们会被拼进那一行、变成文件列表的兄弟，代码列随即被挤到几十像素宽、每个字都换行（这个 bug 真出现过；测试里现在有一条结构断言专门盯 `.dshdv-main` 的孩子数）。
- 自动刷新：有两条节奏 —— 有人刚操作过（切范围、切文件、按下刷新、数据变了）时每 4 秒一次，静默 30 秒后降到 20 秒一次；页面隐藏时一律按慢节奏。**任何一次自动刷新都不会让画面闪，也不会重画**：它先读，只有读回来的内容确实不同才替换 ——
  - 逐条按「路径 + 状态 + 行数」比对，没变的行沿用原来的对象（React 因而不会重建这一行）；
  - **对比正文按 hunk 记忆化**（`React.memo` 比 hunk 对象与换行开关），所以一份对比只花它自己那么大的一次代价，而不是每个 tick 花一次；
  - **空 patch 不发布**：`patch()` 先判断这次写入是否真的改变任何可见字段（数组按长度 + 元素同一性比、`totals` 按标量比），全都没变就既不换 state 也不通知订阅者。
  - 实测（工装里量的）：在一个 5 行对比的界面上跑一次静默刷新 —— 修的**之前**是 **75 个元素重建 + 3 行重渲染**（真实文件上千行时就是几千个元素），**之后**是 **0 次 store 通知 / 0 个元素 / 0 次行渲染**，只剩那一次 HTTP 读。
  - 这是刻意的：diff 视图的价值在于把变化摆出来，而不是自己每几秒跳一次。
- 空态、加载态、错误态各有自己的文案和重试入口；「不在 git 仓库里」「这台机器没有 git」「本次会话还没有记录改动」都是**正常答案**，用一条说明横幅表达，不是报错
- 手动刷新 / 切换范围是**交互式读取**，会走加载态（首个画面必须诚实，不能显示上一个范围的残留）

## 已知限制

- **会话范围的对比依赖改动记录器**：`workspaceChanges` 只为活跃会话保留记录，而且只在它确实算出改动时才留下条目（没有工具结果的轮次、当前这一轮尚未结束时都不会有）。Host 因此还会读**会话日志里的 `write`/`edit` 调用**兜底列文件；这些行会标明出处，右侧显示「Host 没有为这次改动留下前后对比」，并提示切到「工作区」看它现在的差异。
- **会话范围按文件取最新一轮**：一个文件改了多轮时，右侧显示的是**最新一轮**的前后对比，不在一个视图里合并多轮。列表会列出改动过的轮次（`changedTurns`）。
- **兜底列表不带行数**：它只知道「哪些文件被文件工具碰过」，不知道改了多少行，所以这些行的 `+n −n` 是空的。
- **未跟踪文件超过 2 MiB 只给状态不给行数**，二进制文件同理。
- **git 范围以 `HEAD` 为基线**：没有提交、没有暂存区语义之外的「和某个提交比较」选择器。
- **Host 半边改动需要重启 DSH**：浏览器半边由 client 模块图按需服务，刷新页面即可更新；但插件 Host 半边的模块不会被热替换，改了 `index.js` / `lib/*.js` 要重启（或让桌面应用重开）才生效。

## 自举

这个插件自己的仓库就是它的演示场：`git init` + 一次初始提交之后，在会话里切到「变更 → 工作区」，agent 每次改动的文件与逐行对比就直接出现在这里（本次加这一行就是为了当场演示这件事）。
